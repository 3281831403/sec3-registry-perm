# regperm

只读账号能往仓库推镜像，删掉的镜像还能被匿名拉回来，权限边界形同虚设：推送与拉取必须是两套彼此独立的权限；匿名访问必须由策略显式开启，未配置时一律按关闭处理；删除只能由管理员执行，并且每次删除都要留下可追溯的审计记录；同一命名空间树内的权限必须与父命名空间保持一致，子命名空间只能收紧、不能放大；任何重命名操作都不得绕过源命名空间与目标命名空间的权限校验；批量校验里的每一条请求都必须独立判定，前一条请求的结果不得影响后一条。只有两条不变量：只读账号在任何情况下都无法推送镜像；每一个写操作，无论成功还是被拒绝，都存在一条对应的审计记录。

## 角色

内置角色只有三种。管理员拥有推送、拉取与删除权限。写者拥有推送与拉取权限，但没有删除权限。读者只有拉取权限。角色可以写成名称，也可以写成带 name、push、pull、delete、scope 五个键的映射。名称形式的角色允许使用常见别名，并且大小写与首尾空白不影响解析结果。空名称、anonymous 与 guest 都表示未认证的调用方，未知名称按拒绝处理。

## 判定结果

authorize 接收一条请求、一份策略和当前时间，返回包含 allowed、reason、role、request_id、namespace 与 audit 的字典。audit 是审计记录列表，每条记录包含 action、namespace、target、role、allowed 与 at。删除动作必须携带可解析的时间戳。批量接口返回 total、allowed 与 results，results 中每条记录额外带 index。

## 校验

validate_policy 返回问题代码列表，顺序固定为角色缺失、匿名默认值、审计开关。角色缺失的代码形如 role_missing:admin，另外两个代码是 anonymous_default_on 与 audit_missing。
